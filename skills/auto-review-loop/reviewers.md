# レビュアー リファレンス

auto-review-loop はレビュアーを **共通インターフェースの背後** に置く（EX-1）。ループ制御
（ラウンド・上限・トリアージ・絞り込み）はレビュアーの種類に依存しない。新しいレビュアーは
この共通形に出力をマップするだけで追加できる。

## 共通インターフェース（EX-1）

- **入力**: 変更 diff（レビュー対象）＋ 観点（perspective）1つ。
- **出力**: 指摘リスト。各指摘は次のスキーマ：

```json
{
  "id": "<round>-<n>",          // ラウンド内で一意
  "reviewer": "claude",          // レビュアー id
  "perspective": "correctness",  // この指摘が属する観点
  "severity": "must-fix",        // must-fix | nit
  "file": "path/to/file",        // 該当ファイル（無ければ空）
  "line": 42,                     // 該当行（無ければ null）
  "title": "off-by-one in loop bound",
  "detail": "..."                // 根拠・再現・修正方針
}
```

- 1 レビュー = 1 reviewer × 1 perspective。スキルはこれを pair 単位で並列に走らせ、
  **全 pair の結果が揃ってから** トリアージに進む（FR-3.2）。
- `severity` は **must-fix**（直すべき）と **nit**（任意）を区別する。トリアージで
  must-fix のうち妥当なものだけが修正対象になる。

## 登録済みレビュアー

### `claude` — Claude サブエージェント（既定・推奨）

`Agent` ツールでサブエージェントを 1 つ起動し、**観点 1 つに絞った** レビューをさせる。

- プロンプトに「変更 diff」「観点」「共通スキーマで指摘リストだけを返すこと」を与える。
- 観点を 1 つに絞ることで、各観点を深く見させる（観点の分業）。
- 複数 pair は **同一メッセージ内で複数の `Agent` 呼び出し** にして並列化する。

### `codex` — Codex（独立した第二意見）

別モデルによる第二意見で盲点を補完する。`codex:` プラグイン経由で呼ぶ。

- **可用性**: レビュー前に `codex:setup`（`Skill` ツール）で Codex CLI の導入・ログインを
  確認する。未導入／未ログインなら起動時にユーザへ伝え、別レビュアーを選ばせる（FR-1.5）。
- **呼び出し**: `codex:` プラグインの runtime 契約（`codex:codex-cli-runtime`）に従い、
  変更 diff ＋ 観点 ＋「共通スキーマで指摘リストだけを返す」指示を渡してレビューさせる。
- **マッピング**: Codex の出力を上記スキーマへ正規化する（`reviewer` は `codex`、
  `perspective` は依頼した観点、`severity` は must-fix / nit に振り分け）。

## 新しいレビュアーの追加手順（EX-2）

ループ制御フローを変えずに追加できる。

1. **この doc に呼び出し方を追記**（可用性チェック・起動方法・並列化の仕方）。
2. **`SKILL.md` の問い 1（reviewers）の選択肢に追加**。
3. **出力を共通スキーマにマップ**するアダプタ手順をこの doc に書く。

これだけで `start-round` の pair 生成・`with_findings` 絞り込み・circuit-check は
そのまま新レビュアーにも効く。
