# daily-report

現在のプロジェクトの Claude Code セッションを、**daily-report 調**の日報にまとめる。
既定は直近 24 時間だが、ユーザが日数を指定すれば複数日を対象にできる。要素の抽出は決定的
ヘルパ `tools/daily_report.py` に任せ、**何を残すか・どう整理するか**の判断は自分で行う。

ヘルパは `${CLAUDE_PLUGIN_ROOT}/tools/daily_report.py` にある。以下のコマンド例の
`tools/daily_report.py` は実際にはこの絶対パスで呼ぶこと。

## 出力フォーマット（厳守）

**作業を大きさで 2 層に整理する。**

- **主要作業（大きいタスク）** — 箇条書きでアイテマイズする。
  - **項目数の上限はこの主要作業に対して効く**。目安は **1 日あたり最大 3 項目**。
    複数日（`--days N`）なら日数に応じて緩めてよいが、詰め込みのために増やさない。
  - **各項目は一行が文章として読めること**。「何を / どう決着したか」が分かる完結した
    文で書く。1 項目に複数の作業を詰め込んだり、単語を羅列したりしない（上限に収める
    ための圧縮で文を壊さない）。
- **その他（小さなタスク）** — 主要に届かない細かな対応（typo 修正・小さな調整・短い
  確認など）は、**最後に「その他」としてまとめて列挙**する。ここは簡潔でよく、複数を
  一行にまとめてもよい。該当が無ければ省略する。
- 日本語、daily-report 調（「〜した」「〜を対応」の完了報告ベース）。雑談・脱線は落とす。

## 手順

### 1. 直近の発話をダンプ

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/tools/daily_report.py"
```

- 既定で **現在のプロジェクト**（カレントディレクトリから判定）の、**実行時刻から遡る
  直近 24 時間**（＝日付をまたぐ範囲）の user/assistant 発話を、セッション別に markdown で
  出力する。`thinking` / `tool_use` / ツール出力・コマンド系のノイズは除外済み。
- **日数を指定する**なら `--days N`。N 暦日（今日を含めて遡る）を対象にする。
  `--date YYYY-MM-DD` と併用すると、その日を終端とする N 暦日の範囲になる。
  ユーザが「ここ 1 週間」「過去 3 日」のように言ったら `--days 7` / `--days 3` を使う。

  ```sh
  python3 "${CLAUDE_PLUGIN_ROOT}/tools/daily_report.py" --days 7
  ```

- 全プロジェクトを横断したいなら `--all-projects`。細かな窓調整は `--hours N`、
  特定の 1 日だけなら `--date YYYY-MM-DD`。1 発話あたりの長さは
  `--snippet-chars N`（既定 280）で調整できる。
- 出力が空（`no transcript activity found`）なら、その旨だけ伝えて終了する。
- **対象日数が増えるほど作業量も増える**。日数に応じて主要作業の項目数を増やしつつ、
  細かいものは「その他」に寄せて整理すること。

### 2. トリアージして大きさで仕分ける

ダンプを読み、各作業を **大きさ** で仕分ける。判断の指針:

- **主要作業**: 一連の成果が出ているまとまり（機能実装・バグ修正・調査の決着など）。
  これを上限内でアイテマイズする。
- 複数プロジェクトにまたがる場合、プロジェクト単位でまとめてよい（例: 「cc-workflow: 〜」）
- 同一テーマの往復（実装→修正→再修正）は **1 項目に統合**する
- 質問への回答だけ・方針確認だけで成果物が出ていないやり取りは、重要でなければ落とす
- **小さな作業**（typo・軽微な調整・短い確認など）は「その他」へ回す。主要作業の枠を
  埋めるために小作業を昇格させない
- 「何を変えたか・何を決めたか」を優先し、過程の細部は省く

### 3. 出力

主要作業の箇条書き → 末尾に「その他」（あれば）の順で返す。前置き・後置きの説明文は
付けない。各主要項目は文章として完結させ、上限に収めるための圧縮で文を壊さない。

## 例（イメージ）

```
- cc-workflow: warp プラグインの hook エラーを調査し、プラグインを完全アンインストールして解消した。
- daily-report スキルに日数指定（--days N）を追加し、作業を大きさで整理する出力形式へ改修した（TDD）。
- ドキュメント整備として R3 と UniRx の差分メモを追補し、main へ push した。
- その他: README の typo 修正、status-line の色味調整、依存バージョンの確認。
```
