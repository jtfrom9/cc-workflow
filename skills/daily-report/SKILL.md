# daily-report

現在のプロジェクトの直近 24 時間の Claude Code セッションを、**daily-report 調**の短い日報に
まとめる。要素の抽出は決定的ヘルパ `tools/daily_report.py` に任せ、**何を残すか**の判断は
自分で行う。

ヘルパは `${CLAUDE_PLUGIN_ROOT}/tools/daily_report.py` にある。以下のコマンド例の
`tools/daily_report.py` は実際にはこの絶対パスで呼ぶこと。

## 出力フォーマット（厳守）

- **アイテマイズ最大 3 項目**（箇条書き 3 つまで）
- **合計 400 字以内**（見出し・記号を含む全文で 400 字。超えそうなら項目を削るか短くする）
- 日本語、daily-report 調（「〜した」「〜を対応」の完了報告ベース、簡潔に）
- 各項目は「何を / どう決着したか」が分かる粒度。雑談・脱線は落とす

## 手順

### 1. 直近の発話をダンプ

```sh
python3 "${CLAUDE_PLUGIN_ROOT}/tools/daily_report.py"
```

- 既定で **現在のプロジェクト**（カレントディレクトリから判定）の、**実行時刻から遡る
  直近 24 時間**（＝日付をまたぐ範囲）の user/assistant 発話を、セッション別に markdown で
  出力する。`thinking` / `tool_use` / ツール出力・コマンド系のノイズは除外済み。
- 全プロジェクトを横断したいなら `--all-projects`。窓の長さを変えるなら `--hours N`、
  特定の 1 日を対象にするなら `--date YYYY-MM-DD`。1 発話あたりの長さは
  `--snippet-chars N`（既定 280）で調整できる。
- 出力が空（`no transcript activity found`）なら、その旨だけ伝えて終了する。

### 2. トリアージして日報に圧縮

ダンプを読み、**直近の実作業の主要な筋**を最大 3 つ選ぶ。判断の指針:

- 複数プロジェクトにまたがる場合、プロジェクト単位でまとめてよい（例: 「cc-workflow: 〜」）
- 同一テーマの往復（実装→修正→再修正）は **1 項目に統合**する
- 質問への回答だけ・方針確認だけで成果物が出ていないやり取りは、重要でなければ落とす
- 「何を変えたか・何を決めたか」を優先し、過程の細部は省く

### 3. 出力

箇条書き（最大 3 項目・合計 400 字以内）だけを返す。前置き・後置きの説明文は付けない。

## 例（イメージ）

```
- cc-workflow: warp プラグインの hook エラーを調査し、プラグインを完全アンインストールして解消。
- daily-report スキルを新規実装（当日の全セッションを横断要約、最大3項目/400字、TDD で追加）。
- ドキュメント整備: R3 と UniRx の差分メモを追補し main へ push。
```
